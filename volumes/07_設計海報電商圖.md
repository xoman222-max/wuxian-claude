## 一句話摘要

把本地影片或有權處理的線上影片，經由文字稿定位、精確取幀、字幕模式分流與視覺 QA，做成 3:4 社交金句 JPG；原生字幕保留畫面像素，腳本字幕才後期繪字，兩者不可混稱。

## 核心內容

- 預設輸出為 1440×1920、3:4，一張使用 5 個遞增時間點：1 張主圖加 4 條字幕帶。
- 預設主圖約占 70%，每條字幕帶約占 7.5%，條間距為 0；字幕較少時把空間留給主圖。
- `sample` 產生候選幀總覽，`band` 預覽字幕裁切帶，`render` 製作原生字幕拼圖，`render-script` 製作後期腳本字幕拼圖。
- 原生字幕模式只保留影片已燒錄的文字像素，不 OCR 重繪、不翻譯、不改字。
- 腳本字幕模式使用已審核的時間點與 `text` JSON，必須標明為後期字幕，不能冒充原字幕。
- URL 模式用 `yt-dlp` 取得使用者有權處理的影片、元資料和字幕軌；字幕軌只是一條時間索引，不能證明畫面本身有燒錄字幕。
- 交付應包含 JPG、時間點 manifest 或 `lines` JSON、多圖總覽，以及逐張視覺與技術檢查。

## 可重複使用的規則

1. 先確認來源權限、來源型態（本地或 URL）與字幕型態（燒錄或獨立軌）。
2. 用文字稿找段落，用真實影片幀校準最後時間點；時間戳不能直接當成穩定畫面。
3. 每張圖只說一個連貫觀點，4–6 句依原片順序推進；避開轉場、黑幀、閉眼、殘字、播放器 UI。
4. 原生模式以畫面像素為唯一文字真相；腳本模式以已審核 JSON 為文字真相。
5. 先修時間點，再修字幕帶邊界，最後才手動調主圖比例；連續三輪仍不穩定就換片段。
6. 不繞過 DRM、付費牆或地區限制。YouTube 需要 Chrome Cookie 時，必須先取得使用者授權，且不匯出、保存或上傳 Cookie。

## 可轉成工具/詞庫的部分

- 可直接安裝為 Codex Skill：`skills/native-subtitle-quote-image/`。
- 可接到「影片理解／Whisper → 選題 → 字幕金句圖 → 社群文案」內容管線。
- `--aspect` 接受任意正數比例，因此可由預設 3:4 改成目前社群視覺常用的 `--aspect 4:5`；例如寬 1440 時會輸出 1440×1800。
- 適合包一個 Windows 工作目錄產生器，固定建立 `source/`、`analysis/`、`previews/`、`output-v1/`。
- 可加入輸出路由：成品 JPG 保留在任務目錄，並依 `D:\codex\AGENTS.md` 再複製一份非覆寫檔名到 `D:\` 根目錄。

## Summary

`Leonxlnx/taste-skill` is a portable Agent Skills repo for improving AI-built frontends. Its central idea is to fight generic "AI slop" by making the agent infer a design direction, tune layout/motion/density, use stricter typography and spacing rules, and verify the interface before shipping. It also includes image-generation-only skills for web/mobile comps and brand boards, which can feed an image-to-code workflow.

## Key Value

- General default: `design-taste-frontend` from `skills/taste-skill/SKILL.md`.
- Current default is v2 experimental, with v1 preserved as `design-taste-frontend-v1`.
- `gpt-taste` is a stricter GPT/Codex-oriented variant with stronger anti-slop and motion/layout enforcement.
- `image-to-code` defines an image-first website workflow: generate references, deeply analyze them, then implement the frontend to match.
- `redesign-existing-projects` is for upgrading an existing codebase after a design audit.
- `brandkit`, `imagegen-frontend-web`, and `imagegen-frontend-mobile` generate reference images only; they are useful upstream of Codex implementation.
- Style-specific routes include soft premium, minimalist editorial, industrial/brutalist, and Google Stitch-compatible design-system output.

## 核心價值

- 不是逐字摘抄，而是重新梳理讀者的理解流程。

5. 用超大字、關鍵標注、層級排版突出重點。
6. 配色、留白、字級、行距要服務手機端閱讀。

## What It Is

`nexu-io/open-design` is a local-first, open-source design-agent workspace positioned as an alternative to Claude Design / Figma-style AI design workflows. It connects existing coding-agent CLIs on the user's machine, including Codex, Claude Code, Cursor Agent, Gemini CLI, OpenCode, Qwen, Copilot CLI, Hermes, Kimi and others, to a skill-driven artifact workflow.

The core idea is not "ask AI for a pretty page" but "give an agent a design skill, a design system, a local project folder, a preview iframe, and export targets." The repo emphasizes artifact-first generation: web prototypes, dashboards, mobile screens, decks, social carousels, posters, documents, images, videos, and HyperFrames-style motion graphics.

## Useful Ideas To Reuse

- Skill folders are treated as files, not hidden plugins: each skill has `SKILL.md`, optional `assets/`, and optional `references/`.
- Design systems are portable Markdown, commonly using a `DESIGN.md` style schema for color, typography, spacing, layout, components, motion, voice, brand and anti-patterns.
- The first turn asks structured discovery questions before generating design. This reduces bad output caused by missing audience, tone, brand, scale and constraints.
- It uses curated visual directions such as editorial, modern minimal, warm soft, tech utility and brutalist experimental. Each direction maps to deterministic palette and font choices.
- Every artifact renders in a sandboxed preview iframe and can be exported. Export targets include HTML, PDF, ZIP, Markdown and agent-driven PPTX.
- The prompt stack is composable: discovery directives, identity/design rules, active design system, active skill, project metadata and skill side files.
- Local persistence is through plain project files plus SQLite, so work can reopen later instead of disappearing with the page.

## Features Noted

## Core Prompt

请创作一张高完成度的「历史人物破框立像档案 / 3D Historical Breakout Biography Poster」。

这不是普通历史海报，而是一张以「中央全身3D历史人物 + 破框前冲动作 + 四周轻质悬浮历史事件簇 + 底部轻量年谱时间轴」为核心结构的高完成度历史人物纪传海报。

画面中央必须是一位完整全身、站立姿态的3D历史人物，人物是整张图最重要的主视觉，具有强体积感、雕塑感、纪念碑感和历史气场。服饰、冠帽、甲胄、纹样、腰带、鞋履、配饰都要符合其时代身份，整体要写实、厚重、有电影级冲击力。人物脚下要有一个轻而稳的纪念碑式台基，负责承托人物，但不能厚重压画面。

人物不能只是普通站立，必须有一个明显的“前冲破框动作”。手部、手臂或所持关键道具（如玉玺、诏书、卷轴、长枪、长剑、兵符、笏板、地图、书卷等）必须朝向观者伸出，形成强烈的近大远小、前后纵深、透视压缩和破出画面的3D冲击。特别注意：前冲出来的关键道具必须完整可见、清晰可辨识，不能被画面裁切到只剩一小截。

围绕人物四周布置 6 到 10 个关键历史节点。不要做成厚重、规整、整齐平铺的小卡片，而要做成“轻质悬浮、多朝向、半透明”的历史事件簇。每个节点可由 2 到 4 个子碎片组成，包括编号、年份、事件标题、简短说明、小型历史场景画面，以及细金线、开放式边框、节点圆点、注释线等。整体感觉应该像历史档案被拆解成轻盈的时间切片，在人物四周悬浮展开，而不是普通信息卡片排版。

这些事件簇要有不同朝向和空间透视关系：有的左倾，有的右倾，有的向内转，有的向外翻，有的高一些，有的低一些，有前后层次，也可以被人物手臂、衣摆、武器轻微遮挡，形成空间纵深。它们应具有玻璃感、亚克力感、微发光边缘、不完整边框和轻度错位叠层，信息详细但视觉上轻，不可压过中央人物。

画面左侧设置大标题【人物姓名】，使用具有东方历史气质的书法感、碑刻感或墨迹感字体。旁边可加入生卒年、身份标签、关键词总结和一句高度概括性的副标题。标题区要稳、简、克制，不要堆满。

底部必须设置一条轻盈、简洁、细致的横向时间轴，串联人物一生的重要年份，并与四周历史事件簇形成对应关系。时间轴更像策展导览线、博物馆时间标尺或历史索引线，可使用细金线、小圆点、简洁年份、小型文字标注和少量装饰节点。不要做成厚重黑色横栏或巨大底部信息块。

背景以米白宣纸、古纸、旧档案纸或浅色博物馆墙面为基础，整体低饱和、干净、克制。可加入淡淡地图纹理、古建筑剪影、文献残片、印章、金色连接线、注释线、节点、疆域轮廓等元素，营造轻盈理性的历史档案展陈感。

整张图必须建立明确对比：

- 中央人物厚重、真实、立体、强光影、强体积；
- 四周历史节点轻薄、透明、悬浮、微发光、精致理性；
- 人物动作前冲、破框，具有空间爆发力；
- 底部时间轴轻盈克制，只负责收束信息。

## Priority Rules

如果不同要求冲突，请优先保证：

1. 中央人物完整全身
2. 前冲道具完整可见且有强烈3D冲击
3. 四周事件簇轻盈悬浮、不是厚重卡片
4. 中央人物“重”，信息系统“轻”
5. 底部时间轴轻量化、清晰、不压画面
