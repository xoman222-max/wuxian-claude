## 一句話摘要

把長篇小說分塊掃描、跨段別名歸併，再以原文逐字引證校驗角色卡，輸出人物設定、英文出圖／音色提示詞與可選的 16:9 角色三視圖報告。

## 核心能力

- 以最多 24 個重疊區塊處理約 33 萬字元，超限會回報 `truncated`，不會靜默截斷。
- 先掃描角色與別名，再依出現區塊權重選角；可把跨章稱呼收斂到同一人物。
- 逐字比對 `evidence`、限制人物重要性枚舉、禁止出圖 prompt 含角色姓名，並檢查語言與風格負面詞的一致性。
- 產出 `<書名>-cast.json`、Markdown、`report.html`；主要角色可用 Codex 內建 `$imagegen` 生成左側半身像、右上三視圖、右下細節條。
- 報告預設中文，支援任意語言；出圖與 TTS prompt 固定英文。內建 `realistic` 與 `ghibli` 兩套完整風格預設。

## 安裝判斷

- 結論：需要安裝。現有 `角色設計` 偏向參考圖分析與一致性設定卡，本技能補上「小說全文抽取、別名歸併、原文證據、報告渲染」的前處理與交付管線，功能互補而非重複。
- 已安裝至 `D:\codex\skills\novel-characters`，Node `v24.15.0` 符合 Node 18+ 要求，無 npm 依賴、無 API key。
- 本機 `node scripts/selftest.mjs`：220 項全部通過；`quick_validate.py`：通過。

## 安全與相容性

- 確定性腳本使用 Node 標準庫；掃描未發現外部命令執行、憑證讀取、檔案上傳或遠端 API 呼叫。
- 唯一 `fetch` 位於渲染後的 HTML，供瀏覽器把報告內的角色圖片複製到剪貼簿。
- 上游只在 macOS + Node 24 測試；本次已在 Windows + Node 24.15.0 完成語法檢查與 220 項自測。
- 上游 `SKILL.md` 的頂層 `version`、`triggers` 不符合本機 Codex 驗證器；已從本地副本移除。觸發語意原本已包含於 `description`，不影響使用。日後更新上游時要重新確認這個相容修補。

## 可重用工作流

1. 指定小說文字檔、報告語言、風格與角色數；未指定時使用中文、`realistic`、前 10 位。
2. 執行 `chunk`，依區塊讀取 `references/roster-pass.md` 完成角色掃描。
3. 執行 `merge` 歸併姓名與別名，再依 `profile-pass.md`、`schema.md` 產出角色卡。
4. 執行 `validate`，修到完全通過才交付。
5. 視需要依 `sheet.md` 逐角出圖，再執行 `render --md` 與 `render --html`。

## 限制與注意事項

- 自動出圖只給 `protagonist`、`major`；用戶可明確要求全出。
- 角色圖的批次風格仍可能漂移，系列一致性要求高時，應把第一張核准圖當後續參考圖。
- 內建出圖不可用時，只交提示詞並清楚說明；不要自動改走需要 `OPENAI_API_KEY` 的 CLI fallback。
- Apache-2.0；本地副本含為 Codex 格式相容所做的最小修改。

# AI 小說工作流與去 AI 味修稿規則

Source: Codex thread, user requested「搜索網路找解決AI寫小說的問題」後實作《負能量評論家》1-5 章重寫與去 AI 味
Date: 2026-06-22
Type: novel_rule
Tags: AI小說, 系統文, 網文, 長篇一致性, 故事聖經, 章節大綱, 去AI味, 毒舌文風, 現代系統文
Tool Potential: high
Prompt Library Impact: yes

## 一句話摘要

以「故事聖經 → 章節目的 → 場景 beats → 正文 → 一致性檢查 → 去 AI 味」作為之後 AI 小說與現代系統文的固定生產流程。

## 核心內容

AI 寫小說不要一次要求整本或整章自由發揮，要先建立可重複使用的寫作框架：

1. 故事聖經：主角、核心慾望、缺口、金手指規則、世界限制、配角關係、禁用套路、文風基準。
2. 章節目的：每章只承擔 1-2 個主要功能，例如系統綁定、首次驗證、道德邊界、第一次爆點、現實風險。
3. 場景 beats：每章先列 5-8 個場景節點，再寫正文，避免段落漂亮但情節不動。
4. 正文生成：用具體事件、對話、截圖、私信、身體反應推進，不用長篇作者講道理。
5. 一致性檢查：每章後檢查角色設定、系統數值、時間線、伏筆、情緒轉折、未更新設定。
6. 去 AI 味：把「這就是、真正的、意味著、不是 A 而是 B」等總結句改成現場動作、語氣、物件、對話或短促內心反應。

## 可重複使用的規則

- 系統文每章要有：現實壓力、系統提示、一次可驗證的收益或代價、章末鉤子。
- 金手指不能只給爽感，也要給限制、成本、風險或倫理邊界。
- 主角不能只會總結道理，要透過行動證明判斷力。
- 每章保留少量金句即可；金句太密會有 AI 味與短視頻文案感。
- 說理段落要優先改成：聊天記錄、截圖、電話、現場反應、配角吐槽、任務面板。
- 配角說話要帶職業身份與利益位置，不要全都像同一個作者在說話。
- 章末鉤子要接下一章具體行動，不只丟抽象危機。
- 少用「反轉金句式台詞」，例如「這不算 X，這叫 Y」「不是事故，是止損」這類句型。偶爾一兩句可以做爽點，但密度太高會像短視頻文案；優先改成沉默、動作、沒說完的話、具體生活反應或更口語的表達。

## 可轉成工具/詞庫的部分

- 模板：現代系統文故事聖經模板
- 模板：每章 2000/3000 字 beats 表
- 模板：系統任務面板格式
- 檢查清單：去 AI 味替換表
- 檢查清單：長篇一致性審稿表

## 對目前專案的用法

寫新現代系統文時，先用此流程生成簡版故事聖經，再按每章目的寫 3-5 章。寫完後做一輪去 AI 味，重點刪減作者總結式旁白，補充主角的具體處境、配角語氣、現實壓力和系統代價。

## 核心結論

男頻網路小說不是單一類型，而是一套以男性讀者市場、長篇連載節奏、升級/破局/掌控感、類型承諾和平台反饋為核心的敘事生態。它可以寫得很爽，也可以寫得很有文學性；關鍵不是堆設定，而是穩定交付「主角面對壓力 -> 做出選擇 -> 取得可感知進展 -> 引出更大問題」的循環。

「男頻」可視為男性向作品的一種網文語境：作品通常從男性視角、男性讀者偏好的問題意識與欲望結構出發，但不等於必須低俗化、物化女性，或讓所有角色服務主角。高階男頻反而需要讓世界自行運轉，讓配角、勢力、資源、規則、輿論與市場都對主角形成壓力。

## 類型地圖

- 玄幻：架空世界建構是核心，常見修煉體系、宗門/王朝/種族/秘境、境界升級、血脈/法則/神通。適合大長篇與強主線。
- 仙俠/修真：更強調道法、長生、宗門、丹符器陣、因果、天劫、正魔秩序。起點語境中的仙俠常更接近修真大類。
- 都市：現代社會、商業、醫術、異能、重生、神豪、娛樂、職場、曖昧關係、家族衝突。爽點通常更短平快。
- 科幻/未來：災變、星際、機甲、基因、AI、虛擬世界、文明競爭。可與修煉或遊戲融合。
- 遊戲/網遊：等級、職業、裝備、公會、競技、版本更新、現實與遊戲互相影響。適合《星門裡的拳術師》這類方向。
- 無限流：代表源頭之一是《無限恐怖》；核心是角色被投入多個任務世界/副本，在規則、資源、隊伍與生存壓力下進化。
- 克系/詭秘/序列流：以《詭秘之主》為代表之一，將職業序列、神秘學、都市/蒸汽/異界秩序、調查與代價結合。
- 歷史/架空：穿越、制度改革、軍政、商業、權謀、技術差。爽點在「現代知識遇到歷史阻力」。
- 系統流/面板流：把目標、獎勵、升級、任務、懲罰外顯。好用但容易偷懶，系統應該製造選擇壓力，而不是替主角解題。
- 反套路/苟道/種田：不靠硬莽，靠資源積累、風險控制、信息差、長期佈局。適合讓主角更像「自由人」而不是天命工具人。

## 平台與商業邏輯

- 起點中文網是男頻網文核心平台之一，早期以玄幻、武俠、軍事等原創網路小說聞名，並建立了 VIP 付費閱讀傳統。
- 閱文集團旗下包含起點、QQ閱讀、創世中文網、Webnovel 等平台，網文不只靠訂閱，也靠影視、動畫、遊戲、有聲、漫畫與海外發行放大 IP 價值。
- 七貓代表免費閱讀與廣告模式的一支，平台也推現實題材徵文與 IP 化。
- 付費模式重視追讀、收藏、月票、打賞、完讀與更新穩定；免費模式更重視開頭刺激、短週期爽點、廣告完讀、章末鉤子。
- 對創作而言，平台不同會改變章節密度：付費站可慢熱但要維持追讀理由；免費站通常更要求前幾章快速給承諾。

## 男頻章法

- 第一章：不要只介紹世界。必須有「主角困境 + 可見衝突 + 一個差異化能力或視角 + 章尾問題」。
- 前五章：只吃一個核心爽點，不要把十幾章內容塞進去。用反覆測試、失敗、改良、旁人反應，把爽點吃乾淨。
- 十章段落：每 10 章最好有一個小閉環，包含目標、阻力、破局、代價、新鉤子。
- 每章核心：單章只放一個主要事件。設定必須嵌在衝突中出現，不能像百科。
- 章尾鉤子：不是一定要生硬懸念，可以是新問題、新資源、新敵意、新規則、新誤會、新機會。
- 爽點設計：爽點不是「主角贏」，而是讀者看見主角用獨特方式處理壓力，並且世界因此產生反應。
- 反覆但升級：同一模式可以重複，但每次必須提高信息、代價、範圍、對手層級或道德難度。

## 男頻常見爽點模組

- 低位逆襲：主角被低估，靠信息差、技術差、心性差、專業差打破局面。
- 可驗證進步：境界、技能、排名、收入、口碑、裝備、地盤、權限、團隊能力都能當進度條。
- 旁觀者反應：不只寫主角感覺，要寫對手、路人、同伴、上層、平台、市場如何錯判或重新評估。
- 規則漏洞：主角不是違反規則，而是理解規則邊界，用合法/灰色/創造性方式破局。
- 資源經營：靈石、功法、情報、時間、信任、人脈、口碑、用戶、流量，都可以是比戰力更好看的資源。
- 世界自運行：主角不在場時，勢力、NPC、玩家、讀者、平台、同行仍然行動。
- 代價與選擇：高階男頻需要讓勝利有成本。成本可以是曝光、債務、敵意、道德負擔、時間損耗、關係裂痕。

## 適用到現有小說

### 《星門裡的拳術師》

- 保持網遊/現實雙線：遊戲內升級與現實武館、直播、剪輯、平台輿論、收入壓力互相拉扯。
- 不要讓拳術成為萬能解。讓錢、信息、時間、社交信任、隊伍排班、NPC制度都成為同等重要的問題。
- 公會、散人、NPC、主播、工作室、平台剪輯號都應有自己的利益邏輯。
- 每 10 章安排一個小閉環：副本/城市任務/輿論事件/現實麻煩，各自收束一部分，再拋下一個更大的問題。

### 《靈網大陸》

- 「自由修夢匠」比「宗門天才」更有辨識度。前期應從市場、玩家體驗、夢戲鋪營收、同行競爭、作品歸屬切入。
- 核心爽點不是林澈有多強，而是他把危險夢境改成可退出、可回放、可重試，讓普通人第一次看見失敗可被保存和學習。
- 每個新功能都應先服務一個小人物問題，再被市場/同行/勢力看見。
- 大勢力可延後出場；先把方遠、周福、第一批玩家、百戲坊、青嵐城西市生態寫活。

## 寫作檢查清單

- 這章有沒有一個明確事件，而不是散設定？
- 主角是否面對了外部壓力，而不是自己講理念？
- 這章的勝利是否有可見代價或新問題？
- 是否至少有一個非主角角色做出主動選擇？
- 世界是否在主角視角外也運轉？
- 類型承諾是否被交付：升級、破局、懸念、情緒、權力/資源變化至少有一項？
- 章尾是否讓讀者想看下一章？
- 是否避免把女性角色只寫成獎品、背景板或崇拜者？

## 後續可用提示詞

「根據無限裡的男頻網路小說研究卡，幫我檢查這 10 章的追讀點、爽點分布、章尾鉤子和世界自運行程度。」

「用男頻章法幫《靈網大陸》設計第 006-015 章，每章一個核心事件，不提前引入大勢力。」

「把這個設定改成男頻可追讀版本：第一章困境、前三章承諾、前十章小閉環。」

## 注意事項

- 男頻不是粗暴等於爽文，也不是只能寫男性凝視。真正能長線連載的作品需要規則、角色、經濟、組織與情緒都能運轉。
- 參考類型套路可以，但不要複製既有作品的角色、職業、地名、招式、標誌性橋段或敘述風格。
- 若用 AIGC 續寫，需要額外做章節字數分布、重複段落、角色狀態、伏筆回收與後設語檢查。

## What It Is

SillyTavern is a locally installed LLM frontend for power users. It is not a model by itself; it is an interface that connects to text generation models, image generation engines, and TTS voice models.

Official repo description: "LLM Frontend for Power Users."

The project began as a fork of TavernAI and has grown into a community-driven open-source tool for AI hobbyists, roleplay users, character-card creators, and prompt-heavy workflows.

## Core Capabilities

- Unified interface for many LLM APIs and backends.
- Character-based AI chat and roleplay.
- Character cards for reusable personalities.
- WorldInfo / lorebooks for keyword-triggered setting injection.
- Mobile-friendly layout.
- Visual Novel Mode.
- Image generation integration with Automatic1111 and ComfyUI APIs.
- TTS / voice model integration.
- Auto-translate.
- Custom UI and many prompt controls.
- Third-party extension ecosystem.

## Supported Model / API Directions

The README mentions many supported providers or backends, including:

- KoboldAI / KoboldCPP
- Horde
- NovelAI
- Ooba
- Tabby
- OpenAI
- OpenRouter
- Claude
- Mistral
- More through extensions and compatible APIs

The user still needs an API key, local model backend, or external generation service. SillyTavern is the chat frontend and orchestration layer.

## WorldInfo / Lorebook Role

WorldInfo, also called lorebooks, is SillyTavern's world-memory system.

Basic idea:

- A lorebook entry has trigger keywords.
- When the chat contains those keywords, SillyTavern injects the matching setting text into the model context.
- This keeps worldbuilding, character relationships, places, factions, rules, and private facts stable without putting everything inside the main character card.

This is useful for:

- Novel worlds
- Game NPCs
- Long-running roleplay
- AI companion settings
- Teaching or coaching characters with domain-specific knowledge
- Product/FAQ chat personas

# SillyTavern 角色卡經濟與製作流程

- Collected: 2026-05-19
- Source: user pasted article

## 核心觀點

文章把 SillyTavern 角色卡視為一種「內容資產」：本質是一個 JSON / PNG 角色卡文件，但它不是單純技術檔，而是包裝了身份、性格、關係、語氣、場景和示例對話的情感產品。

角色卡能被使用或販售的理由：

- 解決內容冷啟動：使用者不用自己想和 AI 聊什麼。
- 建立情感連接：通用 AI 沒有人格，角色卡給出可互動的人設。
- 形成持續價值：喜歡角色的人可能長期使用、收藏、更新或付費。

## SillyTavern 基本使用

SillyTavern 是本地角色扮演聊天前端，可連接 OpenAI、Claude、Gemini、本地 Ollama / llama.cpp 等模型。

基本流程：

1. 下載 SillyTavern：`https://github.com/SillyTavern/SillyTavern`
2. Windows 執行 `start.bat`，Mac/Linux 執行 `start.sh`
3. 打開 `http://localhost:8000`
4. 連接 API 或本地模型
5. 匯入 `.png` 或 `.json` 角色卡
6. 選角色並開始對話

常見角色卡來源：

- CharacterHub: `https://www.characterhub.org`
- Chub.ai: `https://chub.ai`
- Reddit `r/SillyTavern`

## 角色卡基本結構

SillyTavern V2 角色卡常見欄位：

- `name`：角色名字
- `description`：身份、背景、基本設定
- `personality`：性格標籤、說話風格
- `scenario`：目前對話場景與關係
- `first_mes`：第一句開場白
- `mes_example`：示例對話，教模型如何回應
- `creator_notes`：創作者備註、推薦模型、玩法
- `tags`：分類標籤
- `creator`：創作者名稱
- `character_version`：版本號

`mes_example` 是角色味道的核心，應該用多組 `<START>` 對話展示語氣、節奏、表情、小動作、糾錯方式、主動追問方式。

## Lorebook / 世界書

世界書是角色卡的擴展，用於保存背景知識與長期記憶。

用途：

- 世界觀設定
- 專有名詞
- 角色關係
- 使用者重要資訊
- 某些關鍵詞觸發的背景補充

典型格式：

```json
{
  "entries": [
    {
      "keys": ["星際聯邦", "聯邦"],
      "content": "星際聯邦成立於 2157 年，是人類在太空中建立的第一個跨星系政府。",
      "enabled": true
    }
  ]
}
```

## 從零建立角色卡的流程

先回答三個問題：

- 角色是誰：身份、年齡、背景
- 角色目標是什麼：陪伴、教學、創作輔助、模擬訓練
- 使用者和角色是什麼關係：朋友、導師、陪練、客戶、NPC

建議生成順序：

1. 寫 `description`
2. 寫 `personality`
3. 寫 `scenario`
4. 寫 `first_mes`
5. 寫 3-5 組以上 `mes_example`
6. 補 `creator_notes`、`tags`、版本號
7. 匯入 SillyTavern 測試
8. 根據實際對話迭代

## 讓角色更像真人的 7 個方法

1. 加小動作：例如「揉了揉眼睛」「遞過咖啡」「沉默幾秒」。
2. 加口頭禪：讓角色有固定語氣與辨識度。
3. 用 Lorebook 記重要資訊：使用者寵物、偏好、世界觀背景。
4. 用對比塑造性格：開朗但談到家人會安靜、耐心但對自己嚴格。
5. 給角色弱點：怕蟲、不會做飯、容易焦慮、逞強等。
6. 場景切換：咖啡館、公園、深夜電話、下雨天、課後練習等。
7. 測試與迭代：檢查人設、語氣、長短、主動性、AI 味。

## 常見問題與解法

角色忘記前文：

- 提高上下文長度
- 使用 Lorebook
- 用總結功能定期壓縮對話

回覆太長或太短：

- 調整最大回覆長度
- 在 `mes_example` 示範目標長度
- 在 system prompt 約束字數

不符合人設：

- 增加示例對話
- 讓示例涵蓋不同情境
- personality 改成具體行為，而不是抽象詞

AI 味太重：

- 加小動作、語氣詞、停頓、改口
- 讓角色偶爾思考、猶豫、吐槽
- 避免每句都像客服總結

沒人使用：

- 上傳到 CharacterHub / Chub.ai
- 寫清楚角色介紹、適用場景、推薦模型
- 製作預覽圖
- 在 X、Discord、Reddit 推廣

## 可做成工具的方向

這篇內容適合轉成工具站功能：

- SillyTavern 角色卡生成器：輸入身份、關係、目標，輸出 V2 JSON。
- 角色卡人設強化器：檢查角色是否太平、是否有弱點、口頭禪、對比性格。
- `mes_example` 生成器：根據角色定位生成 3-8 組示例對話。
- Lorebook 生成器：把世界觀、關係、記憶點拆成 keys/content。
- 角色卡評分器：評估冷啟動、語氣穩定、人設辨識度、復用性、商業包裝。
- 角色卡商品頁文案生成器：生成介紹、標籤、適用模型、使用場景、預覽文案。

## 對現有角色設計流程的啟發

目前 `角色設計` 偏向視覺卡，這篇提供的是「聊天人格卡」思路。可和現有卡庫分開：

- 視覺角色卡：臉、造型、場景、風格、負面詞。
- 對話角色卡：身份、性格、關係、語氣、開場白、示例對話、世界書。

兩者結合後可做完整 IP：

- 一張視覺角色卡負責出圖一致性。
- 一張 SillyTavern 角色卡負責聊天人格一致性。
- 一組商品頁文案負責分享/銷售。

# 靈網大陸：夢機核心設定修正

來源：2026-05-18 使用者回饋與第31~60章重寫。

- 夢機不是讀取接入者自己的夢。夢機以靈網、夢紋、夢核、符片、場景燈符等構建可接入的夢境副本。
- 接入者是意識接入夢機副本，身體留在現實。副本提供場景、規則、怪物、提示與退出點。
- 接入者的恐懼、記憶、習慣不生成整個夢境，但會影響壓力線、副本回應、聲光強度、個人化錯誤命令與殘留呼喚。
- 羅青卡住不是「心理困住自己」，而是血月長街的退出識別壞掉，白燈被改成身份標記與劇情道具後，錯誤門仍在呼喚他的識別。
- 白燈相關術語統一：識別線、歸身線、門紋、門根。避免用「魂線」把機制寫成玄學抽魂。
- 認門法是現實端重新建立穩定識別，不讓接入者重新進血月長街殘區。核心句型依錯誤命令調整，例如：現實；我不認這扇門；白燈沒有權叫我回去。
- 灰燈不是夢戲道具，不放進副本；它是現實端鎮門、壓低殘門聲、阻斷錯誤呼喚的工具。
- 後續寫作要牢記一句：夢機造副本，人意識入夢；人心不造世界，但會改變夢的回聲。

## 網站定位

Face the FACS / Melinda Ozel 是以 FACS（Facial Action Coding System，面部動作編碼系統）、面部解剖、臉部動畫、AI 表情追蹤、口型同步為核心的資源站。

首頁重點：
- 用視覺化與解剖學方式理解面部動作。
- 服務對象包括動畫師、模型師、rigging、AI / ML 研究、表情追蹤、遊戲與影視角色製作。
- 站內主題涵蓋 FACS 動作單元、臉部肌肉、微笑眼部動畫、Viseme / phoneme 口型、ARKit blendshape 與 FACS 對照、情緒研究批判。

可用於小說：
- 不要只寫「皺眉」「笑了」「眼神一冷」。
- 可以拆成眉、眼瞼、鼻翼、唇角、下巴、頸部、下顎、呼吸與語境。
- 但也不能把單一臉部動作直接等於心理真相。

## 核心原則：臉部動作不是讀心術

網站反覆提醒的一個方向：FACS 描述的是「臉上發生了什麼動作」，不是「這個人一定在想什麼」。

小說寫法：
- 錯：他眼角一緊，所以他是真心笑。
- 對：他唇角抬起，眼周也跟著收緊，可手指仍按在杯沿上沒有鬆。這個笑像是真的，又像是被逼到只能是真的。

寫人物時應該分三層：
1. 臉部動作：眉內側抬起、眉頭壓低、上眼瞼撐開、唇角下壓。
2. 身體與語境：手是否握緊、是否後退、是否避開某人、場景是否有壓力。
3. 角色目的：他想藏什麼、想讓別人看見什麼、不能讓誰看見什麼。

## FACS 動作單元：小說可用轉譯

來源頁：Facial Action Coding System (FACS) Cheat Sheet
https://melindaozel.com/facs-cheat-sheet/

### 額頭與眉

AU1：inner brow raiser，內眉抬起
- 肌肉：frontalis medial portion
- 表現：眉內側、中央額頭上提。
- 寫作用途：擔心、求助、委屈、突然理解、脆弱感。
- 句型：
  - 他的眉心沒有皺，反而往上一提，像一句話剛聽懂，卻不願承認自己被刺到。
  - 她笑著點頭，內側眉卻先抬了一下，那點脆弱被笑意壓回去。

AU2：outer brow raiser，外眉抬起
- 肌肉：frontalis lateral portion
- 表現：眉尾與外側額頭上提。
- 寫作用途：驚訝、懷疑、挑釁、裝作有興趣。
- 句型：
  - 他眉尾抬了抬，像是聽見一個不算聰明的謊。

AU4：brow lowerer，眉頭壓低 / 眉間收攏
- 肌肉：corrugator supercilii、depressor supercilii、procerus 等。
- 表現：眉頭向中間擠、中央額頭下壓。
- 寫作用途：憤怒、集中、困惑、戒備。
- 注意：不要每次憤怒都只寫皺眉。可以搭配下顎、呼吸、手部。
- 句型：
  - 趙猛眉頭往下壓，話還沒出口，下顎先咬住了。
  - 林澈沒有回嘴，只是眉間收了一瞬，像先把風險算了一遍。

### 眼與臉頰

AU5：upper lid raiser，上眼瞼抬起
- 肌肉：levator palpebrae superioris
- 表現：上眼皮往上拉，眼睛睜大。
- 寫作用途：驚嚇、警覺、突然看見危險、強迫自己清醒。
- 句型：
  - 他眼皮猛地撐開，身體還沒退，視線已經先找到了門。

AU6：cheek raiser，臉頰抬起 / 眼周收緊
- 肌肉：orbicularis oculi orbital portion
- 表現：外眼角被擠壓，臉頰上提。
- 常與真笑相關，但不能當作真誠唯一證據。
- 寫作用途：笑意較深、疲憊中的真笑、也可能是社交訓練出的笑。
- 句型：
  - 這次她笑時，眼角也被帶著收了一下，可那不代表她放鬆，只代表她很會笑。

AU7：lid tightener，眼瞼收緊
- 肌肉：orbicularis oculi pre-septal/palpebral area
- 表現：眼周環形收緊，下眼瞼往內眼角推。
- 寫作用途：懷疑、壓迫感、忍痛、強忍情緒。
- 句型：
  - 他眼睛沒有眯起，眼瞼卻收緊了，像把一句難聽話硬按在眼眶後面。

AU45：blink，眨眼
- 快速閉眼再睜眼。
- 寫作用途：思考斷點、被問中要害、壓下情緒。
- 注意：不要濫用「瞳孔一縮」。眨眼、停頓、眼瞼收緊更自然。
- 句型：
  - 她眨了一下眼，慢了半拍才回答。

AU46：wink，眨單眼
- 可作戲謔、暗示、表演式親密，但在真實情緒辨識中不必過度使用。

### 鼻、上唇、鼻唇溝

AU9：nose wrinkler，鼻皺 / 鼻翼與中上唇上提
- 肌肉：levator labii superioris alaeque nasi，常伴隨眉部壓低。
- 寫作用途：厭惡、聞到異味、道德反感、嫌棄。
- 句型：
  - 他鼻翼很輕地皺了一下，像那句奉承比藥渣還苦。

AU10：upper lip raiser，上唇抬起
- 肌肉：levator labii superioris
- 寫作用途：輕蔑、嫌惡、壓住罵人的衝動。
- 句型：
  - 她上唇抬了一點，很快又壓平，像把厭惡收進禮貌裡。

AU11：nasolabial furrow deepener，鼻唇溝加深
- 肌肉：zygomaticus minor
- 表現：上唇被斜向上拉，鼻唇溝變深。
- 寫作用途：微妙的嫌棄、苦笑、複雜笑意。

AU38：nostril dilator，鼻孔擴張
- 寫作用途：怒意、準備發力、深吸氣、恐懼時吸氣。
- 句型：
  - 趙猛鼻翼擴了一下，像先把火吸進胸腔。

AU39：nostril compressor，鼻孔收窄
- 寫作用途：抑制呼吸、嫌惡、壓住反應。

### 唇角

AU12：lip corner puller，唇角上拉
- 肌肉：zygomaticus major
- 表現：唇角向上、向後、向外拉。
- 寫作用途：笑、社交笑、安撫笑、假裝不介意。
- 重要：唇角上拉不等於高興。
- 句型：
  - 他唇角抬起，眼神卻沒有跟上去。

AU13：sharp lip puller，尖銳唇角上提
- 可用於更尖、更不柔和的笑。

AU14：dimpler，酒窩 / 唇角被壓住或往後拉
- Melinda Ozel 把 dimpler 拆成 y-axis / z-axis 等更細變化，補足 FACS 不夠細的地方。
- 寫作用途：忍笑、壓抑、尷尬、把話咬住。
- 句型：
  - 他嘴角被壓出一點淺痕，像笑意到了門口又被他關回去。

AU15：lip corner depressor，唇角下壓
- 肌肉：depressor anguli oris
- 寫作用途：失望、委屈、悲傷、嫌棄、壓住哭。
- 句型：
  - 方遠唇角短短往下一沉，立刻又抬頭，裝作沒聽見。

AU18：lip pucker，唇前突 / 嘟嘴
- 寫作用途：猶豫、親吻、思考、孩子氣、不滿。

AU20：lip stretcher，唇角橫向拉開
- 肌肉：risorius，且此肌肉在人群中變異很大。
- 寫作用途：緊張笑、恐懼時嘴唇橫拉、尷尬、強笑。
- 句型：
  - 他笑得很寬，唇卻被橫向拉薄了，像一張被撐開的紙。

### 下唇、下巴、嘴周

AU16：lower lip depressor，下唇下拉
- 寫作用途：哭前、委屈、嫌惡、露出牙齒。

AU17：chin raiser，下巴抬肌 / 下唇被推起
- 肌肉：mentalis
- 表現：下巴皮膚起皺、下唇被往上推。
- 寫作用途：忍哭、倔強、話哽住。
- 句型：
  - 她下巴先繃了一下，像把哭腔堵在牙後。

AU8：lips toward each other，雙唇靠攏
- 不只是閉嘴，也可能是其他動作後把唇收回。
- 寫作用途：閉嘴、壓住話、恢復表情。

AU22：lip funneler，唇向前收成漏斗狀
- 寫作用途：發「哦」「嗚」等音、驚訝、吹氣、口型。

AU23：lip tightener，唇緊繃 / 唇變薄
- Ozel 區分 horizontal type 與 vertical type，有助於細分緊張、說話與口型。
- 寫作用途：忍耐、憤怒、封口、控制情緒。
- 句型：
  - 林澈把唇壓薄了一點，沒有接那句挑釁。

AU24：lip presser，雙唇壓緊
- 表現：上下唇互相壓住。
- 寫作用途：忍住話、忍怒、保密、尷尬。
- 句型：
  - 周福把嘴唇壓成一條線，像再開口就會把帳本摔出去。

AU28：lips suck，嘴唇內收包住牙
- 寫作用途：緊張、自我控制、思考、壓住反應。

### 下顎與頸部

AU26：jaw drop，下顎放鬆下垂
- 表現：嘴自然張開，不是用力撐開。
- 寫作用途：驚訝、愣住、呼吸失序。

AU27：mouth stretch，下顎用力張開
- 表現：強制張大嘴，和 AU26 的放鬆不同。
- 寫作用途：喊叫、痛苦、恐懼張口。

AU31：jaw clencher，咬緊牙關
- 寫作用途：忍怒、忍痛、決心、壓住爆發。
- 句型：
  - 趙猛沒罵人，只是咬肌一跳，聲音反而低了下去。

AU21：neck tightener，頸部繃緊
- 肌肉：platysma
- 寫作用途：恐懼、忍痛、激動、壓抑哭喊。
- 句型：
  - 她說沒事時，脖頸先繃出一條細筋。

AU25：lips part，雙唇分開
- 是狀態，不一定代表特定肌肉動作。
- 寫作用途：想說話又停住、驚訝、呼吸不穩。

## Viseme / 口型：說話時不要把嘴寫死

來源頁：Viseme Cheat Sheet
https://melindaozel.com/viseme-cheat-sheet/

核心概念：
- Viseme 是 phoneme 的視覺對應單位：不同音在聽覺上不同，但嘴唇 / 舌頭 / 下顎可見形狀可能相同。
- 例如 /f/ 與 /v/ 聽起來不同，但視覺上都常對應到下唇接近上齒。
- 自然語音中的口型比孤立示範複雜，會受個人臉型、共發音、情緒、音量、語速影響。

小說可用：
- 角色說話時，不要每一句都「薄唇輕啟」。
- 可以寫某些音被壓住、吞掉、唇沒有完全閉合，表現情緒與狀態。

### 幾個口型轉譯

/p/ /b/ /m/：雙唇音
- 通常需要雙唇完全或接近閉合。
- 情緒變化：
  - 嘴唇閉不實：虛弱、猶豫、哭後。
  - 閉得太緊：忍怒、緊張、保密。
- 句型：
  - 他說「不用」時，第一個音被嘴唇壓得太緊，像不是回答，是封口。

/f/ /v/：唇齒音
- 視覺上常是下唇靠近上齒。
- 可用於咬字、克制、低聲警告。

/s/ /z/：齒齦摩擦音
- 嘴唇可能較窄，牙齒或舌位參與。
- 可用於冷語、壓低聲音。

/ʃ/ /ʒ/ /tʃ/ /dʒ/：常有唇向前收圓 / funneling
- 可用於「噓」「吃」「說」等聲音的視覺感。

/w/ /r/ /u/：較圓的唇形
- 可用於驚訝、低聲拖長、含混。

寫作提醒：
- 口型不是只為動畫，也能寫情緒。
- 一個人緊張時會吞音、閉唇過重、咬字變乾。
- 一個人故作鎮定時，聲音可能穩，但嘴角、下顎、唇壓會露出用力。

核心概念：

- FACS 來自解剖，因此大部分面部追蹤形狀都可對到 FACS 與肌肉。

常用對照：

- browDown left/right -> AU4 眉頭壓低
- eyeWide -> AU5 上眼瞼抬起
- cheekSquint -> AU6 臉頰抬起 / 眼周收緊
- eyeSquint -> AU7 眼瞼收緊
- eyeBlink -> AU45 眨眼
- jawOpen -> AU26 下顎放鬆下垂（注意與 mouth stretch 不同）
- mouthSmile left/right -> AU12 唇角上拉
- mouthFrown left/right -> AU15 唇角下壓
- mouthPucker -> AU18 唇前突
- mouthStretch -> AU20 唇橫向拉開

- 不要只寫「sad」。

## 重要批判：眼睛不是一切，杜鄉微笑不是萬能

來源頁："It's All In the Eyes" and Other Lies
https://melindaozel.com/its-all-in-the-eyes-and-other-lies/

核心觀點：
- 社交微笑非常普遍，人們常用笑回應 yes/no、hello/goodbye、please/thank you。
- 人們常以為能從眼睛判斷笑容真假，但這不可靠。
- 作者做過一個社群測試：讓人判斷一張 spontaneous/felt smile 與一張 deliberately posed/unfelt smile，超過 170 個回答中約 85% 判錯。
- 靜態照片比影片更容易誤判情緒，而許多情緒研究與技術仍大量依賴靜態臉部資料。
- Ekman / FACS 很有用，但不應被當作情緒判讀的唯一真理。
- Duchenne smile（常見理解為唇角上拉 + 眼周 orbicularis oculi 收縮）不能穩定等同於真誠快樂：有些假笑也會有眼周收縮，有些真笑未必有。
- 臉部肌肉與可見表現存在個體、族群、解剖差異；以白人歐洲臉為基準的研究可能有偏差。

小說寫作轉譯：
- 不要寫「眼角有笑紋，所以他是真心」。
- 可以寫「看起來像真心，但人物仍保留懷疑」。
- 真誠與否應由後續行為、風險選擇、語境一致性驗證。

可用句型：
- 他笑得很完整，連眼角都照顧到了。林澈反而把這個笑記了下來。
- 她的笑看不出破綻。破綻在笑後那一息，她先看了門。
- 那不是假笑。至少不只是。它更像一個練到熟的表情，真情緒經過時，也只能借那張臉出來。
- 眼睛也會撒謊。或者說，人太會學會怎麼讓眼睛看起來誠實。

## 小說人物表情資料庫

### 警惕

臉：
- AU5 上眼瞼微抬，眼睛開大但不誇張。
- AU7 眼瞼收緊，視線停得短。
- AU4 眉頭輕壓。

身體：
- 先看出口。
- 工具、武器、桌角在手邊。
- 回答慢半拍。

句型：
- 林澈先看門，再看那人的手，最後才看他臉上的笑。
- 他眼皮撐了一下，又很快放回正常，像不願讓警覺浮到臉上。

### 忍怒

臉：
- AU4 眉壓低。
- AU23 / AU24 唇壓緊。
- AU31 咬緊下顎。
- AU38 鼻翼擴張。

句型：
- 趙猛沒罵，唇卻被壓薄，下顎繃得像能把話咬碎。
- 他鼻翼擴了一下，下一句話反而更輕。

### 羞恥 / 被戳中

臉：
- AU15 唇角下壓一瞬。
- AU17 下巴繃起。
- 眨眼變多或慢一拍。
- 視線避開。

句型：
- 方遠唇角沉了一下，立刻把那點表情收回去。
- 他先看木牌，再看地面，像那兩個字比旁人的笑更重。

### 假裝鎮定

臉：
- AU12 唇角上拉，但眼周不同步。
- AU24 唇壓緊後再笑。
- 眨眼節奏變亂。

句型：
- 他笑得太平，像每一塊肌肉都知道自己該站在哪裡。
- 她答得穩，嘴唇卻先壓了一下，像把真正的第一句話吞了。

### 害怕但逞強

臉：
- AU5 上眼瞼撐開。
- AU20 唇橫向拉薄。
- AU31 下顎咬緊。
- AU21 頸部緊。

句型：
- 許晏說還能走時，眼睛睜得很亮，唇卻被橫向拉薄。
- 他不是不怕。怕意已經爬到脖頸上，只是還沒被允許進入聲音。

### 真正放鬆

臉：
- 眉間鬆開。
- 眼瞼壓力下降。
- 嘴唇不再壓緊。
- 呼吸變深。

句型：
- 他沒有笑，只是嘴唇終於不再壓著。
- 她看完那行記錄，眼瞼慢慢鬆了，像一根繃了太久的線終於放回桌面。

## 寫《靈網大陸》的直接用法

林澈：
- 不直接寫「他還沒適應」。
- 寫他看門、看手、看驗符、看帳冊，像讀陌生 UI。
- 表面回話穩，唇或手透露壓力。
- 常用：AU7 眼瞼收緊、AU24 唇壓、AU45 慢半拍眨眼、視線先掃出口。

方遠：
- 羞恥與渴望被承認。
- 常用：AU15 唇角短沉、AU17 下巴繃、避開視線、耳根紅。
- 進步後：眼瞼鬆、看人時間變長、說話不再縮尾。

趙猛：
- 怒意、逞強、怕拖累別人。
- 常用：AU4 眉壓、AU31 下顎、AU38 鼻翼、手背青筋。
- 變化：從「咬緊」到「鬆開」，比笑更有力量。

周福：
- 商人式慌張、心疼錢、又想護短。
- 常用：嘴唇壓線、眼睛左右看、肚子先挺出去。

沈素問：
- 表面穩，內部拉扯。
- 常用：社交笑完整，但手指按木匣、眼周停一瞬、唇先壓再說話。

百戲坊顧懷舟：
- 笑得完整，不能從眼角判真。
- 破綻不要寫在笑，寫在他給出的條件、停頓、把問題換成生意語言。

### 3. Viseme Cheat Sheet

### 6. Facial Performance: 3 Essential Tips for Data Capture Protocols

網址：https://melindaozel.com/facial-expressions-facial-data-capture/

抓到的內容類型：
- 面部捕捉流程設計要考慮資料用途、pose 選擇、pose 順序、如何說明與展示。
- 舊式 protocol 常有冗餘表情、不合邏輯組合、效率差。
- 三個核心建議：
  1. Be use case-minded：先看用途。若是協作型 avatar，不必浪費大量時間捕捉極端尖叫臉。
  2. Design for logical flow：類似動作放一起，如眉部 AU 組、眼部 AU 組，並從易到難。
  3. Example imagery and descriptions must match：示例圖與文字指令不能互相矛盾；人會照看到的做，不一定照文字做。
- 口語化提示比專業名詞更易讓表演者做對。例如 chin raiser 可說「push up your bottom lip」。

小說用途：
- 寫夢機/訓練設計時可用：先按用途分組、從易到難、提示不能矛盾。
- 對《靈網大陸》尤其有用：林澈設計夜巡試煉時，不應堆難度，而要按訓練目的排序。

轉譯到《靈網大陸》：
- 第一關教腳步與回燈。
- 第二關教資源節流。
- 第三關教現場變量。
- 多人模式教溝通與共同壓力。
- 每一關都應有明確 training objective，不只是嚇人。

### 7. 8 Signs the FACS Manual Is Not For You

網址：https://melindaozel.com/reasons-the-facs-manual-is-not-for-you/

抓到的內容類型：
- FACS Manual 對專業 facial coding 有用，但不一定適合動畫、AI、臉部追蹤、數位人等現代用途。
- 八個主要限制：
  1. 若你不是要成為 facial coder，Manual 很多規則可能不適合。
  2. 缺少不同角度表情參考，主要是正面圖。
  3. 靜態圖片多，動態表情不足。
  4. 黑白、老舊視覺材料較不利學習。
  5. 臉型、年齡、族群參考不夠多元。
  6. 缺少肌肉與解剖名詞，對理解動作不夠友好。
  7. 對皮膚、血流、軟組織變形等高細節支持不足。
  8. 學習體驗乾，對創作者不友善。
- 推薦 Hjortsjö 的《Man’s Face and Mimic Language》作為理解面部肌肉與表情的免費資源。

小說用途：
- 不要迷信一套表情表。
- 不同角色臉型、年齡、膚色、疲勞狀態，表情可見度不同。
- 靜態表情不如動態轉折有用：寫「表情怎麼變」比寫「表情是什麼」更好。

### 8. Free & Downloadable Vintage Facial Anatomy Books

網址：https://melindaozel.com/free-downloadable-facial-anatomy-books/

抓到的內容類型：
- 推薦可下載的古典解剖書，很多圖像品質高，有些是公共領域。
- 書單：
  1. Carl Toldt, *An Atlas of Human Anatomy for Students and Physicians*，1919，譯者 Eden Paul。作者特別喜歡其插圖，但提醒某些肌肉名/起點可能過時或有錯。

  3. Henry Gray, *Anatomy of the Human Body*，1918。

用途：
- 做 3D 臉部、角色肌肉、繪畫、漫畫、AI 參考時可以回這份書單找古典解剖圖。
- 寫小說不必直接用解剖名詞，但可以理解表情不是一層皮在動，而是肌肉、脂肪、皮膚一起變形。

### 9. Viseme Variability: Gritted Teeth & Muted Speech

網址：https://melindaozel.com/viseme-variability-gritted-teeth-muted-speech/

抓到的內容類型：
- 從 AI lip sync / audio-to-face 技術角度分析語音與口型變異。
- 沒有單一嘴型能定義某個語音；所謂「正確嘴型」取決於共發音、語速、音量、情緒、下顎緊張度、個人習慣等條件。
- 以《Severance》角色 Gemma 一句台詞為例，她以咬牙、口型壓抑的方式說話，聽覺上清楚，但唇讀與口型辨識會非常困難。
- /p/ /b/ /m/ 通常被視為穩定閉唇錨點，但現實中也有 labiodentalization 等變體，不一定完全閉合。
- 課程 All About Lipsync 更深入：speech variability、linguistic foundations、jaw/lips/tongue/teeth、coarticulation、canonical viseme 為何不可靠、speech vs emotion 等。

小說用途：
- 寫「咬牙說話」時，口型會被壓縮，不是標準清楚張合。
- 忍怒、忍痛、恐懼時，語音可能清楚，但嘴唇看起來不配合。
- 可以寫：「他每個字都聽得清，嘴卻幾乎沒張開，像把怒意關在牙後。」

### 10. Facial Blanching and Blood Flow

網址：https://melindaozel.com/facial-blanching-blood-flow/

抓到的內容類型：
- 討論 facial blanching：臉部或局部皮膚變白 / 失色。
- 臉部不只靠表情傳達狀態，血流、張力、汗水、膚色變化都能反映身體內部變化。
- Blanching 一般指因血流受限造成皮膚暫時變白或變淡。
- 局部 blanching：手指或物體壓住皮膚，移開後會看到短暫白痕。
- 廣泛 blanching：可能與情緒壓力、身體負荷、創傷、感染、失血、脫水、燒傷、凍傷等相關。

小說用途：
- 不只寫臉紅，也可以寫「血色退下去」。
- 但要謹慎，不要每個驚嚇都寫臉色慘白。
- 可用在高壓、強忍、失血、恐懼、接入夢境後身體反應。

句型：
- 他唇上那點血色先退了，話才慢半拍落下。
- 指節被木牌邊緣壓白，鬆開後白痕還停了一息。
- 她不是臉紅，是整張臉像被燈火抽走了暖色。

### 11. Squishy Faces & Expressions

網址：https://melindaozel.com/squishy-faces-expressions/

抓到的內容類型：
- 臉部體積不會憑空產生或消失。
- 表情時，肌肉推擠或拉開周圍軟組織：肌肉、皮膚、脂肪。
- 一處鼓起，另一處通常會變薄。
- 3D 角色若沒有處理這種深度/體積變化，表情會看起來怪。

小說用途：
- 臉部表情不是平面貼圖。
- 可以寫「臉頰被笑意推起」「唇被壓薄」「下巴皮膚皺起」「眼下肉被擠出細紋」。
- 尤其寫真笑、強笑、忍哭、咬牙時，軟組織變化比抽象情緒更有畫面。

AI / 3D 用途：
- 提示詞可加入 volume shift, soft tissue compression, cheek bulging, lips thinning, chin wrinkling。

### 12. /p/ /b/ /m/ Bilabial Visemes & the Importance of Asymmetry

網址：https://melindaozel.com/m-b-p-bilabial-visemes/

抓到的內容類型：
- 每個人的表情與說話都有不對稱性。
- /p/ /b/ /m/ 這類雙唇音通常需要嘴唇閉合，但閉合時左右臉、鼻翼、唇角可能一側被拉得更明顯。
- 這些個人化不對稱可讓 3D / 動畫角色更真實，也可用於理解或改進 deepfake。

小說用途：
- 不要寫每個角色口型都完美對稱。
- 角色緊張或疲憊時，一側唇角可能先動、一邊鼻翼先拉、一邊臉更緊。
- 可用來寫「辨識度」：某人說謊前總是左唇先壓住，某人叫名字時右鼻翼會跟著動。

句型：
- 他說「沒事」時，左邊唇角先壓下去，像那一側臉比他本人更不會撒謊。
- 她每次咬住「不」字，右邊鼻翼都會被唇角牽動一點。

### 13. Cheek Raiser vs. Lid Tightener

網址：https://melindaozel.com/sd/cheek-raiser-vs-lid-tightener/

相關 AU：
- AU6 cheek raiser，臉頰抬起 / 眼外側收緊
- AU7 lid tightener，眼瞼收緊 / 下眼瞼往內眼角方向收
- AU12 lip corner puller，唇角上拉，常污染 AU6/AU7 判讀

抓到的重點：
- Orbicularis oculi 是眼周環形肌，但不同區段收縮會造成不同表情。
- AU6 主要牽涉 orbital area，影響外眼角、上外側臉頰、魚尾紋、眼周外側壓縮。
- AU7 主要牽涉 palpebral area，動作更集中在下眼瞼、內眼角與淚阜附近，會讓眼睛更像「被壓緊」。
- AU6 可出現在快樂、悲傷、疼痛等情境，不只代表真笑。
- AU7 可出現在憤怒、睡意、專注、挫折、看不清等情境，不只代表怒意。
- 單一 AU 不能直接定義情緒。要用上下文。
- 做資料捕捉或建模時，很難取得純 AU6 或純 AU7，兩者常互相污染。
- 若 AU12 同時出現，唇角上拉會推動臉頰脂肪，使 AU6/AU7 更難分。

小說用途：
- 眼周不是只寫「眼睛一眯」。
- AU6 更像外眼角與臉頰被笑意或疼痛推起。
- AU7 更像下眼瞼往內壓，帶著忍耐、專注、懷疑、怒意或疲倦。

句型：
- 她笑時臉頰確實抬起，外眼角也被擠出細紋，可那不代表放鬆；那笑像一個熟練的動作。
- 他沒有瞪人，下眼瞼卻往上壓了一點，像把不耐煩鎖在眼眶裡。
- 林澈看見的不是笑，而是笑裡那點過度用力的眼瞼。

### 14. Inner Brow Raiser: Deep Dive

網址：https://melindaozel.com/inner-brow-raiser-deep-dive/

相關 AU：
- AU1 inner brow raiser，內眉抬起，medial frontalis 收縮。

抓到的重點：
- AU1 是內側額肌造成的眉內側 / 中央額頭上提。
- 乾淨的 AU1 參考很難找，因為很多人做 AU1 時會連帶啟動 AU2 外眉抬起或 AU4 眉頭收攏。
- 有些教科書或資料中的 AU1 圖可能混入 corrugator supercilii，也就是眉間收攏 / 皺眉肌。
- 看到中央額頭垂直線或波紋時，可能不是純 AU1，而是 AU4/皺眉肌污染。
- AU1 的可見位置不一定只在眉毛最內端，可能稍微偏外，取決於個體解剖。

小說用途：
- AU1 常適合寫脆弱、擔心、求助、受傷但還在忍。
- 不要把「眉心皺」和「內眉抬」混在一起。前者更像壓下/集中/怒，後者更像提起/脆弱/困惑。

句型：
- 方遠的眉內側抬了一點，那表情不像反駁，更像先被那句話碰疼了。
- 她沒有皺眉，眉心反而往上一提，像想問，又怕答案已經在眼前。

### 15. The Secret Life of Inner Brow Raiser

網址：https://melindaozel.com/the-secret-life-of-inner-brow-raiser/

相關 AU：
- AU1 inner brow raiser
- AU2 outer brow raiser

抓到的重點：
- AU1 是 medial frontalis，AU2 是 lateral frontalis。
- AU1 可單獨動，也可和 AU2 組成完整 brow raise。
- AU1 是人類面部表情裡很有特色、很難刻意純粹做出的動作。
- 相較許多表情，AU1 在 posed expression 裡很難乾淨誘發。
- 跨物種面部解剖比較中，人類能分開內眉與外眉的動作具有特殊性。

小說用途：
- AU1 很適合寫「控制不住的一點脆弱」，因為它比唇角下壓更細。
- 高控制型角色若短暫出現 AU1，可表示被戳中或真情緒漏出。

句型：
- 顧懷舟笑得很完整，只有眉內側短短提了一下，快得像不是給人看的。
- 林澈把那一瞬記下來。不是破綻，至少是壓力。

### 16. Animation Tips For Smiles

網址：https://melindaozel.com/animation-tips-for-smiles/

相關 AU：
- AU6 cheek raiser
- AU7 lid tightener
- AU12 lip corner puller

抓到的重點：
- 動畫中常見錯誤：用 AU7 lid tightener 過度表現「笑眼」。
- 現實中的笑有很多型，不存在唯一正確的笑。
- 很多喜悅型笑容會有 AU6 + AU12，但兩者也可缺一。
- AU6 和 AU7 都屬眼周肌肉，但可見重點不同。
- AU6 偏外眼角與臉頰的 pinching/compression。
- AU7 偏下眼瞼向上、向內眼角推。
- 若把所有笑都做成 AU7 眼瞼緊，就會讓角色笑得僵、假或壓迫。

小說用途：
- 寫笑時要區分「臉頰被笑意推起」和「眼瞼緊」。
- 假笑、壓迫式笑、營業笑可偏 AU7/AU12。
- 放鬆笑可寫臉頰自然上提、下顎鬆、眼瞼不過度用力。

句型：
- 那笑不冷，卻緊。眼瞼壓得太用力，像笑也要守規矩。
- 她這次笑時，臉頰先動，眼角後動，整張臉終於不像在完成任務。

### 17. Building Smiles - The Right Way

網址：https://melindaozel.com/building-smiles-the-right-way/

相關 AU：
- AU12 lip corner puller
- AU10 upper lip raiser
- AU11 nasolabial furrow deepener
- 其他上唇抬肌可能參與開口笑

抓到的重點：
- 文章限定把「smile」定義為 AU12 / zygomaticus major 拉動唇角。
- 閉口笑：雙唇保持閉合。
- 開口笑：雙唇分開，可能因 AU12 力量足夠，也可能因其他上唇提升肌參與。
- 開口 + 下顎開啟笑：唇分開且下顎打開，可能由下顎開啟、AU12 強度、其他唇部動作共同造成。
- 對動畫/表情建模來說，不能用一個 smile shape 同時承擔閉口與開口笑。
- 直覺上用 AU10 upper lip raiser 去分開上下唇，可能是錯誤做法；笑的開口方式需考慮 AU12 與下顎/唇部組合。

小說用途：
- 笑有閉口、開口、下顎打開三種質感。
- 忍笑多半閉口或唇壓。
- 真正放鬆、被逗笑，可能下顎也鬆開。
- 緊張笑常唇角拉，嘴唇卻壓著或橫向變薄。

句型：
- 他笑得沒有露齒，唇角卻被拉得很遠，像把真話鎖在閉合的唇後。
- 周福終於笑出聲時，下顎先鬆了，那口氣像從胸口掉下來。

### 19. Breaking Down Nose Wrinkler (AU9)

### 21. Bias In Emotion Tracking

網址：https://melindaozel.com/bias-in-emotion-tracking/

抓到的重點：
- 機器不是天生比人少偏見；人類標註和訓練資料會把偏差帶進模型。
- 許多 face/emotion tracking 公司引用 FACS，但沒有真正正確使用。
- 不正確或不一致的 FACS 標註會導致：
  - 表情分類錯誤
  - 標註不一致
  - 種族、文化、年齡相關偏差
  - 模型奇怪地把錯誤表情綁在一起
- 面部動作很細微，需要長期訓練才能區分。
- 很多看似可信的 FACS 參考資料也可能有錯。
- 若公司不投資資料品質、標註規則與專業人員，表情追蹤會出現系統性偏差。

小說用途：
- 寫 AI / 靈網 / 夢機辨識情緒時，不要讓系統完全準。
- 系統可能把老人臉的唇角下垂誤判成悲傷，把文化差異誤判成冷漠，把疲勞誤判成怒。
- 林澈設計夢機時應避免「直接判斷情緒」，改記錄行為和壓力線。

《靈網大陸》可用規則：
- 夢機不判斷「你害怕」。
- 夢機只記：壓力線、回燈視線、停步時間、呼吸波動、退出方式。
- 情緒解讀交給修夢匠和記錄，而不是讓機器下結論。

### 23. Bypassing VR Headset Occlusion in Face Tracking

網址：https://melindaozel.com/bypassing-vr-headset-occlusion-in-face-tracking-preview/

相關 AU：
- AU1, AU2, AU4, AU5, AU6, AU7, AU9, AU10, AU12

抓到的重點：
- 即使看不到整張臉，也能從局部皮膚變化推測部分表情。
- 不一定要看見眉毛，才能判斷眉部是否抬起或皺起；不一定要看見鼻子，才能推測鼻皺。
- 每個面部動作會造成獨特的鼓起、拉伸、皺紋、皮膚移動。
- 有足夠的資料、範例與高品質視角時，可以從有限視野推測部分 AU。

- 不要被 AU 名稱誤導。例如 cheek raiser 雖叫臉頰抬起，但眼眶與外眼角也有重要線索。

小說用途：
- 角色不必看完整張臉，也能從局部看出線索。
- 但這仍不是讀心，是「線索」。

句型：
- 林澈看不到那人的嘴，只看見下眼瞼往內一緊，就知道這句話至少不是全然輕鬆。

### 24. Mindful Design: Emoji Design

網址：https://melindaozel.com/mindful-design-everything-you-did-and-didnt-want-to-know-about-emoji/

抓到的重點：
- Emoji 是溝通輔助，不只是可愛圖案。
- Emoji 用於補足文字中的情緒價值、語氣、意圖、非語言暗示。
- 設計 Emoji 時應為使用者與功能服務，而不是設計師個人喜好。
- Unicode 標準化名稱與實際使用意義可能脫節。
- 不同平台設計差異會造成跨平台理解問題。
- 有些表情很難靠臉本身穩定表達，例如厭惡常需要嘔吐等道具輔助。
- 「pouting face」等名稱和大眾理解可不同，語言與使用會演化。

小說 / AI 用途：
- 表情符號與臉部表情一樣，意義取決於使用場景。
- 同一個笑臉在不同人手裡意義不同。
- 寫通訊、靈網訊息、角色簡訊時，不要把 emoji 當固定情緒，而要看關係與語境。

《靈網大陸》可用：
- 靈網傳訊符可以出現簡化表情符，但不同宗門/商會/年齡層解讀不同。
- 林澈可用「符號語氣會誤判」的思路設計夢機提示：不要只靠符號，要加文字與行為選項。

## 實際抓取後新增的寫作規則

1. 寫表情時優先寫「變化過程」，不要只寫結果。
   - 例如：眉尾先動、唇壓住、眼瞼收緊、下顎再放開。

2. 寫說話時口型要受情緒影響。
   - 忍怒：牙關與下顎限制口型。
   - 虛弱：閉唇不完整。
   - 害怕硬撐：唇橫向拉薄，音節變短。

3. 寫臉色時加上血流與壓力。
   - 臉紅、發白、局部白痕、唇色退、耳根熱，都比抽象「緊張」更具體。

4. 寫角色辨識度時加入個人不對稱。
   - 某角色總是右唇角先動。
   - 某角色忍笑時左臉更明顯。
   - 某角色說謊時不是眼神飄，而是某個音閉唇過重。

5. 寫訓練 / 夢機設計時用 data capture protocol 思路。
   - 先定用途。
   - 同類動作放一起。
   - 從易到難。
   - 提示與示例不能矛盾。
   - 不要堆極端刺激，除非用途就是測極端。

6. 不要迷信單一表情資料。
   - FACS Manual 有價值，但不等於所有創作需求。
   - 靜態圖不足以理解表情；動態、角度、解剖、軟組織、文化/臉型差異都要考慮。

# 情緒、心理學、微表情：小說寫作用資料

日期：2026-05-15

用途：寫小說時描寫人物情緒、警惕、壓抑、謊言、羞恥、恐懼、憤怒、心動、崩潰、克制與人際拉扯。尤其適合《靈網大陸》這種需要寫入夢壓力、陌生世界警覺、修行者互相試探、角色不把話說滿的場景。

## 核心原則

1. 微表情不是讀心術，只是線索。
   - 不能寫成「他嘴角一抖，所以他一定在撒謊」。
   - 更可信的寫法是「嘴角一抖 + 話說太快 + 避開視線 + 手指按住袖口 + 前後語境矛盾」。
   - 情緒判斷要靠多個信號疊加：臉、身體、聲音、語速、距離、動作中斷、場景壓力、人物過去。

2. 情緒通常先於理性語言。
   - 人不是先完整想清楚「我害怕」，才表現害怕。
   - 常見順序：刺激出現 -> 身體先變 -> 微表情漏出 -> 人試圖控制 -> 語言補救。
   - 小說可以寫「他還沒想明白自己怕什麼，手已經先按住了門框」。

3. 壓抑情緒不等於沒有情緒。
   - 壓抑通常只減少外顯表情，不一定降低內在感受。
   - 可以寫表面很平，身體卻有殘留：肩頸繃緊、呼吸變短、吞嚥、手心汗、指節泛白、視線固定在一點。

4. 臉部表情必須放進身體與場景。
   - 研究提醒：單看臉不一定能準確判斷情緒，身體姿態與背景會強烈影響辨識。
   - 小說寫法：不要只寫「他笑了」，要寫他在哪裡笑、笑給誰看、笑完做了什麼、身體是否配合。

5. 情緒可用「觸發物」寫深。
   - 角色不是突然怒、突然怕，而是某件事碰到他的記憶、利益、羞恥、信念或安全感。
   - 例：方遠怕退場，不是怕夢境本身，而是怕退場後再被笑。

## 五大常用情緒族

參考 Paul / Eve Ekman 的情緒地圖思路：許多研究者認為至少有幾類核心情緒特別穩定，包括愉悅、憤怒、恐懼、悲傷、厭惡。寫作時可以把它們當「情緒家族」，不要只寫單一詞。

### 恐懼

功能：保命、避險、準備逃跑或僵住。

常見觸發：
- 陌生環境
- 規則不明
- 身體失控
- 權力不對等
- 可能受罰
- 過去創傷被喚起

外顯：
- 眼睛睜大，掃視出口
- 呼吸變淺
- 聲音壓低或斷句
- 身體後撤，腳尖偏向出口
- 手摸武器、工具、門框、衣袖
- 話變少，先觀察

內在寫法：
- 胃部下沉
- 背後發涼
- 耳邊聲音變遠
- 手指感覺不真實
- 腦中反覆計算出口、風險、誰能信

小說句型：
- 他沒有立刻問話，先看門、窗、櫃台下方，最後才看向說話的人。
- 那人笑得很客氣，林澈卻先記住了他右手離刀柄有多近。
- 他聽懂了三成，裝作聽懂了七成，剩下的全記在心裡。

### 憤怒

功能：防衛邊界、反擊不公、恢復控制感。

常見觸發：
- 被羞辱
- 被誤解
- 權益被侵犯
- 規則被破壞
- 自尊受損

外顯：
- 下顎繃緊
- 眉頭壓低
- 盯視
- 動作變硬
- 手掌握拳或反覆鬆開
- 語速變快，句子變短

內在寫法：
- 胸口發熱
- 太陽穴跳
- 耳根發燙
- 想立刻打斷對方
- 注意力只剩對方一句話

小說句型：
- 趙猛笑了一聲，笑意沒到眼底，手背上的青筋先浮了起來。
- 他本來想罵，話到嘴邊又咽回去，只把木牌捏得咯吱作響。
- 林澈聽見那句話時，第一反應不是回嘴，而是把能惹出麻煩的人全數點了一遍。

### 悲傷

功能：接受失去、降低行動、尋求連結。

常見觸發：
- 失敗
- 被放棄
- 無力挽回
- 關係斷裂
- 希望落空

外顯：
- 眼皮沉
- 視線向下
- 肩膀塌
- 語速慢
- 對周圍反應變鈍
- 手放在膝上或身側，不再主動

內在寫法：
- 胸口空
- 喉嚨堵
- 身體變重
- 對聲音反應慢半拍
- 不想解釋

小說句型：
- 他沒有再辯，只低頭看著自己的木牌，好像那上面少了一個他原本該有的名字。
- 方遠想說自己不是怕，可那句話太輕，還沒出口就散了。

### 厭惡

功能：排斥污染、不潔、道德髒污或令人反感的人事物。

常見觸發：
- 血腥、腐敗、惡臭
- 卑劣行為
- 被迫接觸不願接觸的人
- 對方虛偽、諂媚、貪婪

外顯：
- 鼻翼微皺
- 上唇抬起
- 身體後仰
- 避免碰觸
- 把物品用兩指拎起

內在寫法：
- 胃部翻動
- 舌根發苦
- 想擦手
- 想離遠一點

小說句型：
- 周福看著那枚沾了黑泥的靈石，嘴角抽了一下，最後還是沒伸手。
- 那股甜膩香氣一進門，林澈就把呼吸放輕了半拍。

### 愉悅 / 放鬆

功能：靠近、連結、恢復能量、願意嘗試。

常見觸發：
- 被理解
- 風險降低
- 小成功
- 被公平對待
- 看見希望

外顯：
- 眼周放鬆
- 肩頸鬆開
- 呼吸變深
- 嘴角自然上揚
- 動作變柔
- 願意多說一句

內在寫法：
- 胸口變輕
- 手指暖起來
- 胃口回來
- 注意力開始能分給旁人

小說句型：
- 方遠看著「乙下」兩個字，先是愣，然後才慢慢笑起來。
- 林澈沒有跟著笑，只把記錄牌翻過去，筆尖停了一息。

## 微表情與細節庫

### 想掩飾害怕

- 先看出口，再看人。
- 笑得太快。
- 問題回答得很完整，但沒有反問。
- 手指藏進袖子。
- 肩膀固定不動，像怕露出抖。
- 對突然聲音反應過大，隨後立刻裝作沒事。

### 想掩飾憤怒

- 嘴角短暫下壓。
- 下顎肌肉跳一下。
- 笑意只在嘴上。
- 說話變客氣，稱呼變完整。
- 手上動作慢下來，像怕一快就失控。
- 把原本要說的話換成更平的句子。

### 想掩飾羞恥

- 耳朵或脖子發紅。
- 視線避開熟人，卻偷看陌生人的反應。
- 先反駁，再降低音量。
- 手摸鼻尖、衣領、袖口。
- 把失敗說成「沒什麼」。
- 對安慰反應比對嘲笑更大。

### 想掩飾心動 / 在意

- 先否認，再多看一眼。
- 記住對方無關緊要的小動作。
- 對普通句子反應過度。
- 整理衣袖、頭髮、坐姿。
- 話題繞開本人，卻一直回到本人身上。

### 想撒謊或藏事

注意：不能只靠一個動作判斷撒謊。要寫「基準行為改變」。

- 平時話多的人突然精簡。
- 平時少話的人突然解釋過度。
- 答案太快，像早準備好。
- 避開關鍵詞，用模糊稱呼。
- 說時間、地點、人物時順序混亂。
- 被問到細節時先重複問題。

小說句型：
- 他答得太快，快得像不是在回憶，而是在背。
- 那人說「沒見過」時，眼睛卻往櫃台後方偏了一瞬。
- 林澈沒有追問，只把那一瞬記下來。

## 身體情緒地圖：寫作轉譯

參考 Nummenmaa 等人的「Bodily maps of emotions」研究：不同情緒常伴隨不同身體部位的主觀感受。寫小說時不要機械套用，但可以當素材。

- 恐懼：胸口緊、胃下沉、手腳發冷、背後發涼。
- 憤怒：臉熱、胸口熱、手臂有力、下顎繃。
- 悲傷：胸口空、喉嚨堵、身體沉、眼眶酸。
- 厭惡：胃翻、鼻翼皺、喉頭緊、想後退。
- 羞恥：臉熱、耳根熱、想縮小、想低頭。
- 焦慮：胸口悶、指尖躁、呼吸短、反覆確認。
- 放鬆：肩頸鬆、呼吸深、手指暖、視線變柔。

## 寫警惕的穿越主角

林澈是遊戲設計師，不是天生江湖老手，所以他的警惕應該像「系統設計師在陌生規則裡保命」：

1. 少說話，先收集資料。
2. 不急著暴露自己不懂本地常識。
3. 把陌生詞當 UI 名稱記下。
4. 看人先看權力結構：誰能命令誰、誰敢插嘴、誰在付錢。
5. 每次做動作前先想最壞後果。
6. 用原身記憶補空白，但不完全信任。
7. 對「免費好意」保持懷疑。
8. 對夢機先做最小可逆改動，而不是大改。

可用句型：
- 林澈沒有立刻接話。他先確認自己站的位置離門不遠，工具包還在手邊。
- 原身記憶裡有這個稱呼，但記憶像被水泡過的紙，能看見字，不代表能信。
- 他聽不懂那句話裡的規矩，只聽懂了周福忽然閉嘴。
- 在弄清這裡誰能殺人、誰能罰錢、誰能封鋪前，他不打算把話說滿。

## 夢機情緒描寫規則

1. 入夢者聽不到外面的人說話。
2. 外界只能看投影、壓力線、回燈狀態、進度變化。
3. 入夢者能看到夢內提示，不等於能接收外界喊話。
4. 若要即時引導，只能透過事先設計的夢內 UI：提示閃爍、回燈變亮、壓力警示、錯誤回放。
5. 入夢者在夢裡的情緒，應由夢境刺激與自身記憶觸發，而不是由外面觀眾直接影響。

例：
- 錯：門外笑聲鑽進夢境，林澈對他喊「退出不是輸」。
- 對：方遠看見回燈，忽然想起上次退場後那些笑聲，手指停在半空。外面的林澈看見壓力線升高，卻不能喊，只能盯著回燈亮度是否足夠。

## 對話寫情緒

不要讓角色直接說完整心理分析。用停頓、轉話題、少說半句。

### 害怕

- 「我不是怕。」他說完才發現自己聲音太低。
- 「門能從裡面開吧？」
- 「先說清楚，壞了算誰的？」

### 憤怒

- 「你再說一遍。」
- 「原來你們這裡是這麼算帳的。」
- 「行，我記下了。」

### 羞恥

- 「我剛才只是手滑。」
- 「誰說我要退？」
- 「別看我。」

### 警惕

- 「這話誰說了算？」
- 「規矩寫在哪？」
- 「先試一次，別動核心。」

## 寫作檢查清單

每段情緒戲可以檢查：

- 角色為什麼在這一刻有這個情緒？
- 他想讓別人看見，還是想藏？
- 身體哪裡先反應？
- 表情有沒有和語言矛盾？
- 他下一個動作是靠近、逃避、攻擊、僵住、討好，還是轉移話題？
- 場景有沒有加壓：旁觀者、規矩、錢、身份、時間限制？
- 這個情緒有沒有推動情節，而不是只裝飾人物？
